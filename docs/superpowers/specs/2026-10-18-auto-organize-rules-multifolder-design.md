# Автосортировка, правила с папкой назначения, несколько папок, `#prefix`

Пункты 1–4 из `TODO.md`. Ориентир — Easy File Organizer (Qiplex), у которого это главные отличия от нас.

## Зачем

Сейчас FileSorter — инструмент «открыл, разложил, закрыл». Пользователь хочет, чтобы программа сама поддерживала порядок в папках вроде `Downloads`, а также могла за один раз разложить несколько папок, каждую по своим правилам. Опыта использования такого функционала у пользователя нет, поэтому поведение по умолчанию должно быть безопасным и предсказуемым без настройки.

## Цели

1. **Настройки у каждой папки свои** (профиль папки) — основа для всего остального.
2. **Автосортировка** папки: при появлении новых файлов и/или по расписанию, в фоне, с иконкой в трее и автозапуском с Windows.
3. **Правила с папкой назначения** вместо нынешних правил-фильтров.
4. **Несколько папок за один клик**.
5. **Группировка по общей части имени** (`#prefix`).

## Не цели

- Мобильные/кроссплатформенные UI (это пункт 10 бэклога). Но вся новая логика — в `FileSorter.Core` без WPF.
- Сортировка по содержимому файлов, метаданным фото кроме даты, Batch — бэклог.
- Облачные папки, сетевые диски как особый случай.

## Анти-цели (провал, даже если «работает»)

- Автосортировка **ломает загрузку** в браузере (перенесла недокачанный файл).
- Автосортировка **гоняет файлы по кругу** (разложила → пересортировала уже разложенное → после Undo тут же разложила снова).
- Пользователь **теряет файлы** или не может отменить автоматическое действие. Действует правило проекта: файлы пользователя никогда не удаляются.
- Программа **тормозит систему** в фоне (постоянное сканирование, хеширование больших папок).
- Программа **неожиданно висит в трее**, когда автосортировка не включена.

## Решения

### 1. Профиль папки

Все настройки, которые сейчас глобальные, переезжают в профиль конкретной папки:

- способ сортировки, шаблон подпапок, гранулярность даты;
- быстрые фильтры по категориям (вкл/выкл фильтров и набор включённых категорий);
- папка назначения, перенос/копирование, «включать подпапки», «пропускать дубликаты»;
- правила (см. п. 3) и режим для файлов, не подошедших ни под одно правило;
- настройки автосортировки (см. п. 2).

Глобальными остаются: тема, вид отображения (Tree/Icons/List/Details), список папок, «запуск вместе с Windows».

Поведение:
- Список «Recent» превращается в **список папок** (у каждой — свой профиль). Выбор папки в списке подставляет её профиль в UI; любые изменения в UI сохраняются в профиль выбранной папки.
- *(решение Claude)* Список **управляется пользователем**: открытая папка добавляется в список, но **ничего не вытесняется автоматически** (лимита в 10 больше нет) — удаляется только вручную. Иначе просмотр других папок молча стирал бы профиль и автосортировку `Downloads`.
- *(решение Claude)* Новая папка получает **встроенные значения по умолчанию** (как у новых настроек сейчас). Отдельного редактируемого «профиля по умолчанию» нет.
- Хранение: в `settings.json` (через `JsonFileStore`). *(решение Claude)* **Миграция:** глобальные настройки из старого `settings.json` копируются в профиль **каждой** папки из старого списка недавних и текущей папки — так их поведение не меняется. Правила раньше в `settings.json` не сохранялись, поэтому переносить нечего; старые флаги `ApplyRules`/`RulesAndMode` отбрасываются.

### 2. Автосортировка

**Настройки в профиле папки:**
- вкл/выкл (по умолчанию выкл);
- «при появлении новых файлов» (по умолчанию вкл, когда автосортировка включена);
- «по расписанию: каждые N минут/часов/дней» (по умолчанию выкл);
- в UI удобная кнопка «включить авто с текущими настройками».

**Что именно разбирается:**
- только файлы **в корне** папки (подпапки, в том числе уже созданные сортировкой, не пересортировываются), независимо от флага «включать подпапки» для ручной сортировки;
- пропускаются незаконченные загрузки: `.crdownload`, `.part`, `.partial`, `.tmp`, `.download`, `.opdownload`, а также файлы, которые сейчас открыты другой программой (не удаётся открыть на эксклюзивное чтение) — они будут взяты при следующем срабатывании;
- файл берётся, только если он не менялся ~30 секунд (размер и время изменения стабильны).

**Режим «копировать» в автосортировке** (решение пользователя: копирование разрешено):
- оригинал остаётся в корне, поэтому у каждой папки есть **журнал обработанных файлов** (путь + размер + время изменения), который хранится в `%LocalAppData%/FileSorter/` через `JsonFileStore` и переживает перезапуск;
- файл из журнала с теми же размером и временем изменения повторно не копируется и не хешируется; изменённый файл считается новым и копируется снова (обычные правила имён и дубликатов);
- *(решение Claude)* в журнал попадают и файлы, скопированные **ручной** сортировкой этой папки, — чтобы автосортировка не дублировала уже сделанное вручную;
- *(решение Claude)* при отмене операции записи о её файлах удаляются из журнала (симметрично переносу: после снятия паузы файлы будут обработаны снова); записи о файлах, которых больше нет в корне, вычищаются при каждом запуске;
- в режиме «переносить» журнал не нужен: перенесённых файлов в корне уже нет.

**Срабатывание:**
- режим «новые файлы» — `FileSystemWatcher` на корень папки; события копятся, запуск через ~30 с тишины (debounce), затем проверка стабильности файлов;
- режим «расписание» — таймер; запуск разбирает все подходящие файлы в корне;
- одновременно для одной папки выполняется не больше одной сортировки (ручной или автоматической); автозапуск не стартует, пока идёт ручная сортировка или отмена, и наоборот;
- *(решение Claude)* **защита от «пинг-понга» между папками:** при сохранении профиля — предупреждение, если папка назначения (или полный путь в правиле) лежит внутри другой папки с автосортировкой или папки вложены друг в друга; во время работы движок игнорирует события о файлах, которые он сам только что положил в отслеживаемую папку;
- при старте программы с включённой автосортировкой выполняется одна проверка папки (то, что накопилось, пока программа не работала).

**История и отмена:**
- каждый автозапуск, который что-то переместил, — отдельная запись в истории с пометкой «авто» и именем папки, отменяется как обычная;
- **отмена любой операции папки ставит её автосортировку на паузу** (иначе программа тут же разложит файлы обратно); в UI папки видно «на паузе», снять паузу — одной кнопкой.
- *(решение Claude)* **лимит истории** считается отдельно: последние 50 ручных операций и последние 200 автоматических — чтобы активная `Downloads` не вытесняла ручные операции.
- *(решение Claude)* кнопка «Отменить» в главном окне отменяет **самый последний запуск**, ручной или автоматический (каждая запись истории получает идентификатор запуска и признак «авто»).

**Фон и трей:**
- если хотя бы у одной папки включена автосортировка, крестик окна сворачивает программу в трей; при первом таком сворачивании показывается подсказка «FileSorter продолжает работать в трее»;
- если автосортировка не включена ни у одной папки, крестик закрывает программу, как сейчас, и иконки в трее нет;
- меню иконки в трее: «Открыть», «Приостановить всё» / «Возобновить», «Выход»;
- *(решение Claude)* «Приостановить всё» — отдельный глобальный флаг; «Возобновить» снимает только его, паузы отдельных папок (после отмены) остаются. Обе паузы сохраняются между запусками; пока действует пауза, проверка при старте не выполняется;
- уведомление после автосортировки: «Downloads: разложено N файлов» с действием «Отменить» (если уведомлений слишком много — объединять, не чаще одного раза в ~30 с на папку);
- в списке папок индикатор: авто включено / на паузе / выключено.

**Автозапуск с Windows:** глобальная настройка; запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` с аргументом (например `--tray`), при котором программа стартует сразу в трее без окна.

**Платформа:** движок автосортировки (наблюдение, debounce, расписание, проверка стабильности) — в `FileSorter.Core`. Трей, уведомления и автозапуск — за интерфейсами в `Abstractions/`, реализации в `FileSorter/Platform/`.

### 3. Правила с папкой назначения

- Правило: условия + папка назначения + вкл/выкл.
  - Условия — те же поля и операторы, что сейчас (имя, расширение, даты, размер; `Content` остаётся заглушкой до пункта 6 бэклога), несколько условий в правиле, режим «все условия» / «любое».
  - Папка назначения — **подпапка** внутри целевой папки (`Movies`) или **полный путь** (`D:\Video`).
- Правила проверяются **сверху вниз, срабатывает первое подходящее**; порядок можно менять.
- Файлы, не подошедшие ни под одно правило, — по выбору в профиле:
  - **«разложить обычным способом»** (по способу сортировки/шаблону) — по умолчанию;
  - **«оставить на месте»** — заменяет нынешние правила-фильтры.
- Быстрые фильтры по категориям остаются как есть и применяются до правил.
- Превью показывает папки из правил вместе с остальными.
- Дубликаты, отмена, «уже на месте» работают для файлов из правил так же, как для остальных.

### 4. Несколько папок за раз

- В списке папок можно отметить несколько; «Разложить» обрабатывает каждую **со своим профилем**, последовательно.
- Превью: у каждой отмеченной папки свой корневой узел; диаграмма — по всем отмеченным вместе.
- В истории каждая папка — отдельная запись (чтобы отмена и пауза автосортировки работали по папкам). «Отменить» в главном окне отменяет весь последний запуск (все его записи).
- Если одна папка упала с ошибкой, остальные всё равно обрабатываются; итог в статусе — по каждой.

### 5. `#prefix`

- Новый токен шаблона `#prefix` и новый способ сортировки «Name» среди кнопок способов.
- Значение: имя без расширения, у которого отрезаны хвостовые номера и разделители (`-`, `_`, пробел, `.`, скобки с числом):
  - `hello-world-1.jpg` → `hello-world`
  - `IMG_2034.jpg` → `IMG`
  - `photo (3).png` → `photo`
  - если ничего не осталось → `#`.
- *(решение Claude)* Хвостовые цифры отрезаются и без разделителя: `IMG2034` → `IMG`, `file2` → `file`, `report_v2` → `report_v`.
- Регистр при группировке не учитывается (`Photo-1`, `photo-2` → одна папка; имя папки — по первому встреченному файлу).

## Ограничения

- `FileSorter.Core` — только `net10.0`, без WPF (см. `CLAUDE.md`).
- Правила производительности из `CLAUDE.md`: тяжёлая работа — вне UI-потока; EXIF — только лениво.
- Никогда не удалять файлы пользователя; всё, что делает автосортировка, отменяемо.
- Совместимость с существующими `settings.json` и `history.json` (миграция, см. п. 1).

## Оставлено на решение исполнителя

- Точная вёрстка UI: где в окне живут настройки автосортировки и редактор правил (диалог или панель), как отмечаются несколько папок.
- Конкретные значения задержек (debounce, стабильность файла), если ~30 с окажутся неудобными.
- Механизм уведомлений Windows (balloon tip трея или toast).
- Внутреннее устройство профилей, движка автосортировки и правил; разбиение на классы и интерфейсы.
- Порядок реализации и разбиение на этапы.
